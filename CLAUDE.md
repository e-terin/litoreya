# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Litoreya — веб-приложение для хранения зашифрованных постов (текст, пароль). Шифрование
end-to-end на стороне клиента: **сервер не может расшифровать данные пользователя даже при
полном доступе к БД**. Это не пожелание, а свойство, которое обязан сохранять любой код здесь.

Проектные документы (читать до внесения архитектурных изменений):

- `docs/PLAN.md` — этапы, принятые решения, раскладка на хостинге
- `docs/crypto-design.md` — схема ключей, операции, ограничения
- `docs/DEPLOY.md` — процедура выкладки и обновления, диагностика отказов

## Раскладка

```
backend/    Laravel 12, PHP 8.2 — JSON API, никаких Blade-вью
frontend/   Next.js 16, статический экспорт — SPA
docker/     образ php:8.2-apache, vhost'ы, init-скрипты MySQL
hosting/    шаблон прод-.env и .htaccess для ассетов Next (версионируются)
deploy/     дерево релизов, копия раскладки хостинга (артефакт, в git не попадает)
bin/        сборка, деплой, откат, дым-тест
```

## Команды

```
make setup             первичная настройка (.env, ключ, миграции)
make dev               Next :3000 + Laravel API :8080
make prodlike          собрать релиз и поднять раскладку хостинга на :8081
make test              все тесты (бэкенд + крипто-ядро)
make test-integration  стык крипто-модуля с живым API (нужен запущенный prodlike)
make release           собрать релиз в deploy/litoreya/releases/
make deploy            залить на хостинг и переключить
make rollback          откатиться на предыдущий релиз
make smoke URL=...     дым-тест раскладки
make artisan CMD="route:list"
make clean             снести том БД
```

Локальных PHP/Composer/Node нет — всё выполняется в контейнерах. Одиночный тест:
`make artisan CMD="test --filter=LoginTest"`.

## Где что лежит

```
lib/crypto.ts      схема ключей: конверт, обёртки, шифрование постов
lib/keyvault.ts    хранение мастер-ключа в браузере (IndexedDB, auto-lock)
lib/session.tsx    состояние сессии: аутентификация × разблокировка
lib/api.ts         единственная точка обращения к API, CSRF
lib/vault.ts       слой между шифротекстом сервера и UI
lib/password.ts    генератор паролей, копирование с очисткой буфера
```

`lib/vault.ts` — граница: наружу отсюда выходит только расшифрованное, внутрь уходит только
зашифрованное. Компоненты не должны видеть ни `ciphertext`, ни мастер-ключ.

Все обращения к записям на бэкенде идут через `$request->user()->posts()` и
`->categories()`. Принадлежность обеспечивается формой запроса, а не отдельной проверкой,
которую можно забыть, — не заменять на `Post::find()`.

Аутентификация и разблокировка независимы. Пользователь может быть залогинен, но заперт —
после auto-lock или возврата на следующий день. Отсюда четыре состояния сессии, а не два.

## Ограничения, которые легко нарушить незаметно

Каждое из них уже стоило отладки — не «правильные практики», а конкретные грабли этого стека.

**PHP строго 8.2.** Версия на хостинге. Образ и тест `HealthTest` её фиксируют. Уехать вперёд
локально — значит получить расхождение с продом, которое всплывёт только при деплое.

**Фронтенд обязан оставаться статически экспортируемым.** На shared хостинге нет Node.
Запрещены SSR-зависимости, Server Actions, Route Handlers, `next/image` с дефолтным лоадером,
rewrites в проде. `next.config.ts` включает `output: 'export'` только в production, а rewrites
только в dev — при `output: 'export'` Next 16 роняет и `next dev`, если rewrites присутствуют.
Проверять `make release` при изменениях фронта, а не перед деплоем.

**Никаких замыканий в роутах.** `php artisan route:cache` на них падает, а кеш маршрутов
собирается на сервере при каждом деплое. Только ссылки на контроллеры.

**Front controller — стоковый `backend/public/index.php`, без подмены `SCRIPT_NAME`.**
Раньше он лежал в подкаталоге `/api/` и требовал костыля; теперь папка домена — симлинк
на `public/`, `index.php` оказывается в корне, и `pathInfo` приходит полным сам. Если
подмена `SCRIPT_NAME` вернулась в файл — значит кто-то восстановил старую раскладку;
сборка на это падает.

**`DirectoryIndex` обязан жить в `backend/public/.htaccess`, не в vhost.** На хостинге
vhost нам не принадлежит. Без этой строки корень сайта отдаст `index.php`, то есть
JSON-404 от Laravel вместо SPA.

**В `.htaccess` нельзя убирать блок «существующие файлы и каталоги».** Флаг `[L]` там не
означает «последний»: после подстановки набор правил запускается заново. Этот блок —
условие завершения рекурсии, без него SPA-fallback зацикливается до
`AH00124` и отдаёт 500 на всём сайте.

**`Referrer-Policy` должен оставаться `same-origin`.** Sanctum в cookie-режиме опознаёт «свой»
запрос по `Referer`/`Origin`, а для same-origin GET браузер `Origin` не шлёт. `no-referrer`
сломает авторизацию на всех GET-запросах.

**Тесты идут на MySQL, не на SQLite.** Посты хранятся бинарными блобами; различия типов и
strict mode обязаны вскрываться в тестах.

**Ключевая фраза и открытый текст постов не должны попадать на сервер ни при каких условиях.**
Ни в запросах, ни в логах, ни в сообщениях об ошибках. Любой новый эндпоинт принимает и отдаёт
только шифротекст. Фраза не должна появляться даже как аргумент функции в `lib/api.ts`.

**В `KeyVault` кладётся только неизвлекаемый `CryptoKey`.** Извлекаемый ключ сводит на нет
весь смысл хранилища — его украдёт любая XSS. `store()` на этом падает намеренно.

**Sanctum опознаёт «свой» запрос по `Referer`/`Origin`.** Без них сессия не подключается вовсе
и запрос падает с `Session store not set on request`. Поэтому `Tests\TestCase` проставляет
`Origin` по умолчанию, а домены перечислены в `SANCTUM_STATEFUL_DOMAINS`.

**Маршрут CSRF живёт по `/api/csrf-cookie`.** Префикс Sanctum переопределён в
`config/sanctum.php`: дефолтный `/sanctum/*` на хостинге ушёл бы в SPA-fallback, потому что
`.htaccess` отдаёт Laravel только `/api/*`.

**`config:cache` выполняется только на сервере, никогда при сборке.** В
`bootstrap/cache/config.php` запекаются абсолютные пути сборочной машины и её `APP_KEY`.
На хостинге такой кеш даёт 500 без единой записи в лог — потому что путь до лога тоже
берётся из него. Сборка проверяет, что этого файла в релизе нет.

**`composer install --no-dev` выполняется внутри каталога релиза, не в `backend/`.**
Иначе он вырезает dev-зависимости из рабочего дерева, и локальные тесты перестают
запускаться после каждой сборки.

**Релизы иммутабельны, предыдущий не удаляется сразу.** После переключения симлинка
`current` часть воркеров ещё ~120 с разрешает путь в старый каталог (realpath cache).
Правка релиза на месте или его удаление в этот момент ломает выдачу.

**Число итераций KDF задано в двух местах и должно совпадать:** `KDF_ITERATIONS` в
`lib/crypto.ts` и `CryptoEnvelopeRules::MIN_KDF_ITERATIONS` на бэкенде. Клиент не может
опуститься ниже — сервер отвергнет конверт.

**Предельная глубина дерева категорий тоже задана дважды:** `CategoryParent::MAX_DEPTH`
на бэкенде и одноимённая константа в `lib/tree.ts`. Расхождение проявится не ошибкой,
а 422 на форме, которая по клиентским правилам выглядит допустимой.

**`parent_id` у категории — открытое поле, и это осознанно.** Сервер видит форму дерева,
но не названия. Прятать его в шифротекст нельзя: тогда исчезнут внешний ключ и серверная
проверка, что родитель принадлежит тому же пользователю.

## Раскладка деплоя

Папка домена на хостинге (называется по имени сайта) — симлинк на `public/`
текущего релиза. Локально её роль играет `deploy/webroot`:

```
data/<папка-домена> -> litoreya/current/public
data/litoreya/
    current -> releases/<ts>          переключается атомарно через mv -Tf
    releases/<ts>/                    иммутабельны
    shared/{.env, storage/, backups/}
```

Код приложения лежит вне веб-корня: наружу открыт только `public/`. Статика Next.js
кладётся туда же, рядом с `index.php`, — их разводит `.htaccess`.

`make prodlike` воспроизводит это дерево локально в `deploy/`, включая оба симлинка.
Проблемы с правилами перезаписи, `DirectoryIndex`, SPA-fallback и путями воспроизводятся
только здесь — dev-режим их не ловит.

**Prod-like намеренно не видит живой `backend/`**: он проверяет собранный релиз, иначе не
поймал бы «забыл включить файл в релиз». Быстрый цикл правок — в dev-режиме.

`bin/smoke.sh <url>` — дым-тест раскладки, каждая проверка привязана к конкретной причине
отказа. Проверяет содержимое, а не коды ответа: при SPA-fallback отсутствующий путь честно
отдаёт 200, и проверка по коду показывала бы утечку там, где её нет.
